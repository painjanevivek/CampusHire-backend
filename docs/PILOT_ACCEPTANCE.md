# Controlled Pilot Acceptance Pack

## Participants and data

Use authorized synthetic or minimized pilot fixtures. Record institution, session date, facilitator, student participants, T&P participants, accessibility technology, browser/device, and policy version. Never place credentials, resumes, protected attributes, or production exports in this document.

## Student scenarios

- Sign in, resume profile onboarding, correct saved evidence, and explain what is optional.
- Review the single next readiness action and trace its source facts.
- Search roles, distinguish formal eligibility from semantic relevance, save a role, and submit an eligible application.
- Exercise a needs-review or ineligible explanation without presenting AI output as authority.
- Upload a safe PDF, recover from processing failure, review extraction, reject an unsupported suggestion, generate a version, and download it.
- Select a roadmap, record progress, inspect notifications, and request eligible data deletion.

## Administrator scenarios

- Create and publish a drive/role with versioned eligibility rules.
- Inspect applicants, manual-review reasons, snapshots, and the audit trail.
- Exercise an authorized override with a policy-linked reason; verify a routine reviewer cannot perform it.
- Cancel/retry a background job and inspect its immutable timeline.
- Disable an unavailable AI/provider path while deterministic eligibility and core operations continue.

## Accessibility and resilience

Complete each critical flow by keyboard, at 200% zoom, in a narrow viewport, with reduced motion, and with the pilot screen reader. Exercise offline, unauthorized, empty, loading, failed, retry, closed-deadline, stale-version, and dependency-unavailable states.

## Evidence record

For every scenario record pass/fail, observation, severity, issue owner, target date, evidence link, and retest result. Separate product defects from training or policy questions. Critical/high security, data-loss, cross-tenant, inaccessible-blocker, or dishonest-authority failures block release.

## Decision

The release decision must name the approving product owner, institution T&P owner, privacy/legal owner, accessibility reviewer, and security/platform owner. Choose `approve`, `approve with time-bounded limitations`, or `reject`. This repository provides the pack but does not claim stakeholder acceptance until signed evidence is attached outside source control.
